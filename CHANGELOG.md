# Changelog

## v0.2 (in progress)

- T15 — ffmpeg video export: File > Export video opens a dialog (format MP4 / WebM, resolution as Full / Half / Quarter of the viewport size, frame range defaulting to the scene's full animation range), then renders each frame with the existing render path and pipes packed RGB24 frames to ffmpeg's stdin (new `light_engine/video.py`, stdlib only: libx264 CRF 20 for MP4, libvpx-vp9 CRF 30 for WebM, yuv420p, scene fps). The export runs on the GUI thread with a progress dialog and Cancel — the OpenGL context lives on the GUI thread, so frames must render there, and the loop pumps events after every frame so Cancel works. A cancelled export kills ffmpeg and deletes the partial file; a failed encode deletes its broken output too. Export sizes round down to even dimensions (yuv420p needs them), and the grab packs QImage rows explicitly because bytesPerLine can pad past width*3. Missing ffmpeg is a plain message with the install line (`sudo apt install ffmpeg`), never a crash. The gizmo never appears in an exported video (same suppression as frame export). The tavern renders byte-identically to T14. 284 tests passing.

- T14 — Gizmo undo: one undo step per drag gesture, via the existing live-edit pattern — the viewport fires `gizmo_drag_started` when a handle drag starts (the window snapshots the pre-drag scene) and `gizmo_drag_finished` on release (the window commits the snapshot as one undo step). The snapshot is a full scene copy, so a drag on a keyed frame undoes the key with the base, exactly. A press with no movement, or a drag that ends exactly where it started, pushes no step (the commit skips a snapshot identical to the current scene — same for a slider grabbed and released without moving). Redo is new with T14: there was no redo at all before, so undo now saves the current scene on a redo stack (same 50 cap, cleared by any new edit) and Edit > Redo (Ctrl+Shift+Z / Ctrl+Y) restores it. Also fixed in T14: undo/redo re-sync the viewport's selection after restoring the scene — set_scene clears it, so the gizmo used to vanish after an undo even though the object stayed selected — and undo/redo preserve the camera across the restore (set_scene re-fits the view on the scene centroid and resets the orbit angles, so undoing a move used to yank the view a pixel or two and reset an orbited view to the defaults). Drag math, picking, and snapping are unchanged. The tavern renders byte-identically to T13. 263 tests passing.

- T13 — Gizmo handle picking + dragging: the gizmo handles are pickable and draggable. Ray tests in `geometry.py` (ray vs cylinder segment for the move arrows, ray vs thin ring for the rotate rings, the existing AABB test for the scale cubes) read the same handle constants the drawing uses, so the pick can never drift from what is on screen; a 0.12-unit tolerance fattens the zero-width lines into grabbable handles. A left press on a handle starts a drag (handle wins over object picking and orbit); Move intersects the mouse ray with the plane perpendicular to the camera through the grab point and projects the movement onto the axis, Rotate takes the angle around the axis from the grab point's position on the ring plane (accumulated per step, so a drag past 180 degrees keeps turning), Scale takes the pointer's distance from the centre along the axis as a ratio of the grab distance. Shift snaps: 10 cm / 15 degrees / 0.1. The hovered handle brightens (mouse tracking on, its own VAO per mode+highlight), the dragged handle stays bright, and the inspector spin boxes follow the drag live through a new `transform_changed` signal. A drag writes the base transform — and the key on the current frame when the track has one there, so a keyed object visibly follows the pointer (no key is ever created by a drag). Scale drags clamp at 0.01 per axis so an object cannot collapse or flip. Drags have no undo step yet — that is T14. The tavern renders byte-identically to T12. 244 tests passing.

- T12 — Gizmo drawing + modes: the selected object gets a transform gizmo drawn with the existing `lines` program (no new shader): Move is three arrows (X red, Y green, Z blue) with wireframe cone arrowheads, Rotate is three rings one per axis, Scale is three short lines ending in wireframe cubes. The gizmo is unit-space geometry scaled by camera distance (size = distance × 0.12, about 15% of the viewport height), drawn with the depth test off so it is never hidden inside the object, and shows only while an object is selected. Toolbar buttons above the viewport (Move / Rotate / Scale) + W/E/R shortcuts (Blender convention); the shortcuts fire only when the viewport area has focus, never while typing a name or a number. The gizmo is world-aligned in T12 and follows the object's animated position. Exported frames never include the gizmo: render_frame_to suppresses it for the grab and restores it after (the File-menu still grabs the live viewport as-is, gizmo included, like the selection box). Drawing + modes only — handle picking, dragging, and undo are T13/T14. The tavern renders byte-identically to T11 at equal viewport size. 197 tests passing.

- T11 — .glb export: File > Export mesh as .glb (selected object) and File > Export scene as .glb write a minimal glTF 2.0 binary file (stdlib `struct` + `json`): one scene, one node per object, one mesh per object, one primitive per mesh, non-interleaved bufferViews. Vertices stay in the object's local space and the transform rides on the node as TRS (translation / rotation quaternion / scale), conjugated into Y-up meters, so a re-import restores the object's own position/rotation/scale. Materials carry baseColorFactor, metallicFactor, and roughnessFactor — roughness and metalness survive the round-trip (unlike .obj); only procedural textures are lost. Export scale defaults to 0.01 (cm to m), editable in the export dialog. The tavern exports and re-imports as the same 19 objects and 1,674 triangles, transforms and materials exact. Also fixed in the T9 importer: component type 5123 (UNSIGNED_SHORT) was read as 4 bytes, which misread real-world 16-bit index lists (Blender writes them for small meshes). 183 tests passing.

- T10 — .obj export: File > Export mesh (selected object) and File > Export scene as .obj write an .obj + .mtl pair (Kd base colors, one material per distinct color). Vertices are de-indexed on write and go through each object's world transform (position, rotation, scale); normals go through the inverse-transpose, so non-uniform scale stays correct. Export scale defaults to 0.01 (cm to m), editable in the export dialog, so export-then-import round-trips the geometry: the tavern exports and re-imports as the same 19 objects and 1,674 triangles. Missing mesh assets warn naming the file and are skipped; nothing selected or an empty scene says so plainly. 160 tests passing.

- T9 — .glb import: File > Import mesh reads glTF 2.0 binary files (stdlib `struct` + `json`). One mesh primitive becomes one object; node transforms land on the object's own position/rotation/scale (baked into the vertices only for shear, reflection, or zero scale); baseColorFactor, metallicFactor, and roughnessFactor map to the material; Y-up meters convert to Z-up cm. Skins, animations, cameras, lights, and textures are skipped with a warning, never fatal. Sample: examples/sample.glb (red crate + teal pyramid, 18 triangles). 141 tests passing.

## v0.1 — 2026-11-12

First version. Native Qt + OpenGL window with still scenes, modeling, and animation. 6 primitives, PBR-lite materials, 3 procedural textures, named cameras, PNG stills, outliner + click-select, numeric transforms, 50-step undo, timeline keyframes, PNG frame export. Example tavern scene included. 33 tests passing.
